Resumen ejecutivo

Se desarrolló una función en TypeScript que recibe eventos de Amazon S3, decodifica las keys, limita el procesamiento al prefijo originals/, descarga JPEG o PNG con AWS SDK v3, redimensiona con Sharp y guarda un objeto relacionado en resized/. El nombre determinista hace segura la repetición del evento.

La compilación local, la auditoría de dependencias y el procesamiento de imágenes fueron ejecutados realmente. La configuración cloud se documentó y se representó mediante capturas simuladas debido a la indisponibilidad de la cuenta AWS.

1–2Introducción y objetivos

Introducción

El procesamiento manual de imágenes requiere intervención humana, consume tiempo y dificulta mantener dimensiones uniformes. Una arquitectura orientada a eventos permite reaccionar inmediatamente a una carga y ejecutar una transformación sin mantener servidores encendidos.

Amazon S3 actúa como almacenamiento y productor del evento; AWS Lambda aporta cómputo bajo demanda; Sharp realiza la transformación; IAM controla permisos; y CloudWatch centraliza logs. TypeScript facilita una implementación modular, legible y con validación estática.

Objetivo general

Diseñar e implementar una solución serverless que redimensione automáticamente imágenes JPEG y PNG al almacenarlas en el prefijo originals/ de un bucket S3, preservando el original y guardando el resultado en resized/.

Objetivos específicos

  • Procesar todos los registros contenidos en un evento S3.
  • Obtener dimensiones desde IMAGE_WIDTH y IMAGE_HEIGHT.
  • Conservar el tipo JPEG o PNG y un Content-Type correcto.
  • Evitar ciclos mediante filtro de infraestructura y validación defensiva.
  • Aplicar mínimo privilegio para lectura, escritura y logs.
  • Producir salidas idempotentes y observables.
Alcance: el entregable incluye código, política IAM, empaquetado Linux x64, documentación y pruebas locales reales.

Arquitectura orientada a eventos

UsuarioCarga JPEG/PNG

Secuencia

  1. El usuario carga un objeto dentro de originals/.
  2. S3 emite s3:ObjectCreated:* únicamente si la key coincide con ese prefijo.
  3. Lambda identifica bucket y key, decodifica caracteres y valida extensión.
  4. GetObject descarga el archivo a memoria.
  5. Sharp comprueba el formato real, auto-orienta y redimensiona sin deformar.
  6. PutObject guarda una key determinista en resized/.
  7. Los mensajes de ejecución se escriben en CloudWatch Logs.

Separación de responsabilidades

Evento

S3 detecta una creación y entrega uno o más registros.

Proceso

Lambda y Sharp transforman buffers sin modificar la entrada.

Observación

CloudWatch permite diagnosticar formato, dimensiones y errores.

5Implementación

Implementación de la función

El handler recorre secuencialmente event.Records. Si un registro falla, el error se conserva y se continúa con los demás. Al final se lanza un AggregateError para que una invocación parcialmente fallida no aparente éxito.

export async function handler(event: S3Event): Promise<void> {
  const results: RecordResult[] = [];
  const failures: Error[] = [];

  for (const [index, record] of event.Records.entries()) {
    try {
      results.push(await processRecord(record, index + 1));
    } catch (error: unknown) {
      console.error("Error al procesar registro S3.", ...);
      failures.push(error instanceof Error ? error : new Error(String(error)));
    }
  }

  if (failures.length > 0) throw new AggregateError(failures);
}

Construcción de la salida

originals/viaje/Foto.JPEG se transforma determinísticamente en resized/viaje/Foto-resized.jpeg. No se usan fechas ni identificadores aleatorios.

Validaciones

  • Decodificación de + y caracteres URL-encoded.
  • Prefijo obligatorio originals/.
  • Extensiones .jpg, .jpeg y .png.
  • Comparación entre extensión y formato binario detectado por Sharp.
  • Dimensiones enteras, positivas y menores o iguales a 10 000.

const pipeline = sharp(input, { failOn: "error" })
  .rotate()
  .resize({
    width: dimensions.width,

8Permisos y seguridad

IAM de mínimo privilegio

{
  "Effect": "Allow",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/originals/*"
},
{
  "Effect": "Allow",
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/resized/*"
}

Controles aplicados

  • No se concede s3:*, borrado, administración ni lectura de otros prefijos.
  • El bucket debe permanecer privado con bloqueo de acceso público.
  • Lambda obtiene credenciales temporales a través de su execution role.
  • Las claves de acceso, contraseñas y tokens no aparecen en el repositorio.
  • Los permisos de logs se limitan al grupo de la función, excepto la creación inicial del grupo.
  • La validación binaria reduce el riesgo de procesar un archivo disfrazado.
Auditoría local: la política JSON fue validada y no contiene acciones administrativas con comodín.

Consideraciones de producción

Para una solución pública también serían necesarios límites de tamaño, alarmas, presupuesto, retención de objetos y, si se utiliza una clave KMS propia, permisos KMS restringidos a esa clave.

11Prevención de ciclos e idempotencia

Controles de consistencia

Prevención de ciclos

1. Filtro del trigger

S3 solo invoca Lambda por keys que comienzan con originals/. La salida se escribe en otro prefijo.

2. Defensa en código

El handler vuelve a comprobar el prefijo y termina el registro si recibe una key de resized/ u otra ubicación.

originals/foto.jpg
›
Lambda + Sharp
›
resized/foto-resized.jpg
×
Sin nueva invocación

Idempotencia

S3 puede entregar una notificación más de una vez. El mismo archivo siempre genera la misma key. Una repetición sobrescribe de forma segura el resultado anterior en vez de crear copias numeradas o nombres aleatorios.

originals/foto.jpg
        ↓
resized/foto-resized.jpg  // siempre la misma salida

En una solución con control estricto del costo podrían registrarse key y eTag en DynamoDB con escritura condicional. Para el alcance académico, la sobrescritura determinista satisface la consistencia requerida.

12–13Conclusiones y referencias

Conclusiones

  1. Una arquitectura basada en eventos desacopla la carga de la imagen de su transformación y elimina la necesidad de invocar manualmente el proceso.
  2. Separar originals/ y resized/, junto con una validación defensiva, evita ciclos de invocación.
  3. Sharp conserva proporción y formato, pero sus binarios deben empaquetarse para el sistema operativo y arquitectura de Lambda.
  4. Los nombres deterministas hacen que la entrega repetida de eventos produzca un estado consistente.
  5. IAM y CloudWatch son parte funcional de la solución: reducen exposición y facilitan diagnóstico.
